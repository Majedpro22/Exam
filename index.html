Frage 12: Stream API Pipeline 5,00 Punkte
Vervollständigen Sie die Methode processServerLogs. Eine Liste von rohen Log-Strings soll ausgewertet werden.
Jeder String hat das Format SERVICE_NAME:DAUER_IN_MS (z.B. database:450).
  • Extrahieren Sie nur Einträge, deren Dauer strikt größer als 500 ms ist.
  • Erstellen Sie eine List<String>, die ausschließlich die Namen der Services enthält, die zu langsam waren.
  • Duplikate in der Ergebnisliste sind nicht erlaubt (jeder Service darf nur einmal vorkommen).
Zwingende Vorgabe: Verwenden Sie für die gesamte Logik ausschließlich eine einzige Stream-Pipeline.
Die sichtbare Methodensignatur darf nicht geändert werden. Bearbeiten Sie die markierten Bereiche im Codefeld.

Zum Beispiel:

Test Resultat
System.out.println(processServerLogs(List.of("web:120", "auth:600", "auth:800", "db:900"))); [auth, db] (Reihenfolge irrelevant)

Die Eingabe-Strings werden anhand des Trennzeichens ':' zerlegt, nach Dauer gefiltert, der Servicename extrahiert, Duplikate entfernt und in einer Liste gesammelt.

Frage 13: Thread-Sicherheit mit Monitor-Objekt 6,00 Punkte
Vervollständigen Sie die Klasse HitCounter. Sie wird in einer Serverumgebung eingesetzt, in der mehrere Threads gleichzeitig Aufrufe registrieren.
  • Die Methode registerHit() erhöht den internen Zähler um 1.
  • Es muss zwingend verhindert werden, dass bei gleichzeitigen Aufrufen durch mehrere Threads Updates verloren gehen (Lost Updates).
  • Verwenden Sie den in der Vorlesung gelehrten Mechanismus zum Schutz kritischer Bereiche über ein eigenes Monitor-Objekt (nicht this).
Die sichtbare Methodensignatur und die vorhandenen Felder dürfen nicht geändert werden.

Zum Beispiel:

Test Resultat
// Nach Start von 100 Threads, die je 1000 mal registerHit() aufrufen
System.out.println(counter.getHits());		 100000

Kritische Abschnitte werden mit synchronized(...) und einem internen Objekt vor Race Conditions geschützt.

Frage 14: Endboss - Sensordaten-Auswertung 12,00 Punkte
Schreiben Sie ein komplettes, eigenständiges Java-Programm zur Auswertung von Sensordaten.

Aufgabe:
Erstellen Sie eine Klasse SensorAnalyzer mit einer statischen Methode findCriticalSensors.
  • Eingabe: Ein java.nio.file.Path zu einer Textdatei.
  • Format der Datei: Jede Zeile enthält exakt einen Sensorwert im Format SENSOR_ID;WERT (z. B. Temp-01;45.5).
  • Fehlerbehandlung:
    • Wenn eine Zeile nicht das geforderte Format aufweist (z.B. fehlendes Semikolon) oder der Wert keine gültige Kommazahl (double) ist, werfen Sie eine eigene, checked Exception namens CorruptedDataException.
    • Diese Exception muss die fehlerhafte Originalzeile in ihrer Fehlermeldung enthalten.
    • Wenn die Datei nicht existiert oder eine IOException auftritt, fangen Sie diese und werfen Sie eine RuntimeException (Unchecked).
  • Ausgabe: Die Methode liest die Datei zeilenweise (speicherschonend!) ein. Sie ermittelt alle SENSOR_IDs, bei denen der gemessene Wert größer oder gleich 100.0 ist.
  • Rückgabewert: Eine Set<String>, die die IDs der kritischen Sensoren enthält.
Hinweise: Sie müssen die Klasse CorruptedDataException selbst definieren. Verwenden Sie try-with-resources.

Zum Beispiel:

Test Resultat
Path p = Files.createTempFile("sensors", ".txt");
Files.writeString(p, "Temp-01;45.5\nTemp-02;102.3\nTemp-03;100.0");
System.out.println(SensorAnalyzer.findCriticalSensors(p));		 [Temp-02, Temp-03]
Path p = Files.createTempFile("sensors_bad", ".txt");
Files.writeString(p, "Temp-01;INVALID_DOUBLE");
SensorAnalyzer.findCriticalSensors(p);		 throws CorruptedDataException ("Temp-01;INVALID_DOUBLE")

Die Datei wird speicherschonend mit BufferedReader oder Files.lines eingelesen, zerlegt und bei Formatfehlern mit CorruptedDataException abgebrochen. IOExceptions werden gefangen und als RuntimeException gekapselt.
